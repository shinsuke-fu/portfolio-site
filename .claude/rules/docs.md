# ドキュメントの役割分担

- `設計書.md`：実装済み機能・データモデル・画面構成に加えて、決定の経緯や試行錯誤も含めて
  記録する「生きた設計書」。テンプレートの一般的な方針（経緯を書かず簡潔に保つ）とは異なり、
  このサイト自体が「成長プロセスを記録する」というコンセプトのため、あえて経緯も残す方針を
  とっている
- `学習ノート.md`：初心者向け解説はすべてここに集約する。`設計書.md`側には解説を書かない
- `規約.md`：AI向けの絶対ルール。事実として古くなった記述以外は、AIが勝手に書き換えない
- `引継ぎメモ.md`（ローカル）：中身は持たせず、Claude Projectのドキュメント
  `claude/引き継ぎメモ.md`への案内のみを書く。実体はProject側に一本化している（理由は
  `CLAUDE.md`の「ドキュメント構成の方針」を参照）
- `TODO.md`：今後やること・将来検討する事項の一覧。完了したものは削除せず`[x]`にして残す
- `デプロイ手順.md`：Git/GitHub/Vercelの操作手順書。ユーザーはターミナルよりVSCodeのGUI操作が
  中心という前提で書く
- コミットメッセージは、まとまった変更のたびにチャット上で提示する運用（別ファイルは作らない）
