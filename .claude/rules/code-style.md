# コード品質ルール（src全般）

- **ファイルヘッダーコメント**：新規にコンポーネント／主要ロジックファイルを作るときは、
  ファイル先頭に以下の形式のコメントブロックを付ける。
  ```
  /**
   * src/xxx/Yyy.tsx
   * -----------------------------------------------------------------------
   * 【役割】
   *   （このファイルが何を担当するか）
   * 【主な処理】
   *   1. （処理の流れを箇条書きで）
   * -----------------------------------------------------------------------
   */
  ```
- **`any`を使わない**：型エラーは、Propsの渡し漏れやimportパスの不整合を疑って直す
- **非自明なロジックには「なぜ」を書く**：処理内容の説明だけでなく、なぜその実装になっているかを
  コメントで残す（例：`FadeInSection`をカスケードレイヤーで囲んだ理由、tilt演出をJSにした理由など）
- **アイコンのみのボタンには`aria-label`を付ける**：`ThemeToggle`・ハンバーガーメニューで
  すでに実施している基準を踏襲する
- **実装済みの機能を、固定文字やダミーコードに書き換えない**（デグレ禁止。`規約.md`4章参照）
